# Railway 架構改造設計

## 目的
將既有 salon bonus v7.3 改成可部署在 Railway、由 PostgreSQL 保存共用資料的應用，完成驗證後推送 jason121380/south_bonus 的 main 分支。保留繁體中文介面、原本產品選單與現有補助規則；不新增業績／廣告費或報表入口。

## 架構
- 一個 Node.js/Express 服務提供靜態前端與同來源 /api 路由。
- Railway PostgreSQL 使用 DATABASE_URL 連線，密碼不送至瀏覽器。
- 前端維持原生 HTML/CSS/JavaScript，拆分 API 存取與計算邏輯。
- Dockerfile、健康檢查與 README 提供 Railway 部署方式；啟動時監聽 0.0.0.0 與 PORT。

## 資料與規則
- 廣告補助、流量補助、業績、廣告費各自逐筆儲存；設定獨立儲存。
- 兩種補助各自限制每位設計師每月一筆；重複新增顯示提示，更新走明確編輯操作。
- 補助金額與門檻由後端重新計算，不能直接信任瀏覽器傳入結果。
- 保留現有 5% 廣告費加成、3.5 倍 ROAS 與流量補助門檻。
- 更新附帶版本檢查，遇到其他裝置更新時提示重新載入，避免靜默覆蓋。

## 存取與遷移
- 個人帳號登入，角色只有 admin（管理員）與 user（一般用戶），以 HttpOnly cookie 與資料庫 session 維持登入，密碼以 scrypt 加鹽雜湊。
- 管理員可以新增帳號、調整角色、停用或啟用帳號、重設密碼，並操作全部紀錄。一般用戶只能查看、新增、修改、刪除自己的紀錄；後端每個 API 都檢查角色與 owner_id。設定、目標、報表與匯出也依相同權限限制。
- 首位管理員透過 BOOTSTRAP_ADMIN_USERNAME 與 BOOTSTRAP_ADMIN_PASSWORD 環境變數建立，不提供公開註冊或預設密碼。重設密碼與停用帳號撤銷既有 session，禁止停用或降級最後一位有效管理員。
- 移除雲端選單、Supabase 表單與上傳下載操作；登入後直接讀寫 Railway PostgreSQL。
- 舊 localhost 的 localStorage 不清除。提供獨立舊資料匯出工具；於正式網址登入後可在設定匯入 JSON，資料歸登入者所有。匯入驗證欄位並以交易處理，衝突保留既有資料並回報；使用者可自行選擇部分紀錄另行匯入。
- 新資料只有 API 成功後才視為儲存；離線時提示連線失敗，不假裝已同步。
